# Notes for Claude

## Logging, crashes and debug screens come from the shared library

`com.lukeneedham:common` (source: `LukeNeedham/ci-workflows`, `common/`; docs: `docs/using-the-library.md` there) provides the logger, crash handler and debug pages. Do not write our own.

- Log with `Logger.d/i/w/e(message, ...)` (`com.lukeneedham.common.logger.Logger`). Never use `Log.*` or `println`.
- `DebugKit.init(DebugKitConfig(enabled = BuildConfig.DEBUG))` is the first thing in `App.onCreate`.
- `Root` (called only by `MainActivity`) wraps the UI in `ProvideDebugSettings`, the library's single provider of debug composition locals. Keep it wrapped even if a screen reads no setting yet, so a setting added to the library later reaches every screen. Every animation with an explicit duration passes it through `LocalAnimationSpeed.current.scale(ms)` so the debug speed setting applies: the screen transitions (`ScreenTransitionMillis` in `AppNavigation.kt`) and the page turn (`PageTurnState.settle`, which gets the speed from `rememberPageTurnState`). Give any new animation an explicit duration and pass it through `scale`. Animations that use the default spring (`ContentsSheet`'s `AnimatedVisibility`, `Modifier.animateItem()`) are not affected by the setting.
- The `Route.Debug`, `Route.Logs` and `Route.Crashes` routes (`navigation/Route.kt`) are registered only when `BuildConfig.DEBUG`; the "Debug" row on the Settings page (`ui/settings/SettingsPage.kt`, shown only in debug builds) opens them. The shared `DebugPage` shows only the library's own things and has no slot for app-specific tools; the app has none yet. When it gets some, make an app debug page for them with a button that opens the library's page.
- The library comes from the Maven repo in `settings.gradle.kts`; change its version in `gradle/libs.versions.toml`.

## One view model per page, never shared

- Every page has a view model of its own (`ShelfViewModel`, `BookViewModel`, `SearchViewModel`, `SettingsViewModel`, `HistoryViewModel`, `BinViewModel`, `BinBookViewModel`, `BinPoemViewModel`) and none is shared between pages: no activity-scoped or app-wide view model, and a page never reaches another page's. Create a page's view model in its `XPage` with `appViewModel { ... }` (`ui/AppViewModel.kt`); `AppNavigation` gives each back stack entry its own view model store, so a view model lives as long as its page is on the back stack.
- What several pages need lives below the view models, in the repositories in `data/`: `PoetryRepository` (database, settings, the write lock, and `writes`, which changes after each write so search can read again) and `HistoryRepository` (the notepad and history caches that the book and history pages both show). Both are singletons got with `get(context)`.
- `Route.Book(bookId, poemId)` carries the book to read, so `BookViewModel` opens it itself; a finished edit is saved when the app stops and when the book page is left (`onCleared`).
